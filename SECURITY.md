# Security

## Reporting a vulnerability

Please report security issues privately, not in a public issue.

- Preferred: GitHub's private vulnerability reporting on
  <https://github.com/ekstremedia/profile-photo-generator/security/advisories/new>
- Or email **terjen@gmail.com** with `[ppg security]` in the subject.

Useful things to include: what you can do with it, how to reproduce it, the
version or commit, and whether it needs `PPG_API_KEY` to be unset.

This is a small project maintained in spare time. Expect an acknowledgement
within a week. Fixes go out as a patch release and the report is credited in
[CHANGELOG.md](CHANGELOG.md) unless you would rather it were not.

Supported: the latest release on the default branch. There are no long-term
support branches.

## Standing operational warnings

These are properties of the design rather than bugs. They are here because they
will bite an operator who does not know about them.

### The API is unauthenticated by default

`PPG_API_KEY` is empty out of the box, so `docker compose up` works with no
configuration. In that state anyone who can reach the port can generate images,
list every avatar you have generated, and delete them.

**Set `PPG_API_KEY` before exposing the service to anything except localhost.**
Clients then send `Authorization: Bearer <key>`.

Two things to know about the check:

- It covers `/v1/avatars*`, `/v1/jobs*` and `/v1/images/generations`. It does
  **not** cover `/v1/options`, `/healthz`, `/readyz` or `/metrics` — those
  expose no images and are useful to monitoring. Block them at your reverse
  proxy if that is not acceptable.
- A bearer token in a URL is not possible, so an `<img src>` tag cannot
  authenticate. If you set a key, proxy image requests through your
  application; [docs/LARAVEL.md](docs/LARAVEL.md) shows how.

Also review `PPG_CORS_ORIGINS`, which defaults to `*`.

Generation is expensive and serialised behind one GPU, so an open endpoint is a
denial-of-service surface as much as a data one. `PPG_MAX_QUEUE` bounds the
queue; it does not bound how long someone can keep it full. Put a rate limit in
front of a public deployment.

### `OLLAMA_HOST=0.0.0.0` opens port 11434 to your network

Reaching a host Ollama from inside Docker requires the Ollama daemon to listen
on more than `127.0.0.1`. Setting `OLLAMA_HOST=0.0.0.0:11434` exposes the
Ollama API — including model management — to everything that can route to the
host.

Mitigations, best first:

- Bind to the Docker bridge address instead of `0.0.0.0`.
- Firewall port 11434 to the Docker network.
- Skip it entirely: `PPG_COMPOSER=template` needs no Ollama, and the template
  prompts are good.

### Generated images are synthetic, and say so

Every written file carries provenance metadata: PNG text chunks and EXIF
containing `AIGenerated: true`, the note "Synthetic image. Generated by a
diffusion model. Depicts no real person.", the model id, the backend, the seed,
the prompt and the attributes.

This is deliberate and worth preserving. If your pipeline re-encodes or
optimises these images, check that it does not strip the metadata; if it does,
carry the provenance somewhere else. Publishing synthetic faces of people who
do not exist without any marking is the thing this project is trying not to do.

Note that the metadata includes the full prompt and persona. If that is
sensitive in your context — a prompt containing internal terminology, say —
strip it deliberately rather than accidentally.

### The content filter is narrow, and not a classifier

`src/ppg/safety.py` is a word and phrase filter over free text
(`prompt_extra`), plus an instruction in the LLM composer's system prompt. It
refuses three categories: sexual content, age descriptors, and phrasings that
reach for a real, identifiable person. The attribute axes themselves come from
a curated vocabulary and cannot express anything problematic. Ages are clamped
to `PPG_MIN_AGE`–`PPG_MAX_AGE` (18–90 by default), and going below that floor
requires `PPG_ALLOW_MINORS=true`, which also forces plain school-portrait
framing and drops all styling overrides.

What it is not:

- It is not an image classifier. Nothing inspects the pixels. The diffusers
  safety checker is deliberately off, because it false-positives constantly on
  ordinary portraits.
- It is not exhaustive. It is a list of words in a Python file. It does not
  understand paraphrase, other languages, or obfuscation.
- It does not know who is real. There is no celebrity database, on purpose — a
  partial one would give false confidence.

The default model is NSFW-capable. The filter blocks the obvious route to that
on the way in; it does not make the model incapable of it.

**Operators who need stronger guarantees should put real moderation in front of
the API**: a proper text classifier on inputs, an image classifier on outputs,
or both, plus whatever logging and review your context requires. The filter
here is a narrow, auditable floor, not a ceiling.

### Everything runs locally, including your data

No prompt, attribute, image or persona leaves the machine, unless you configure
`PPG_BACKEND=openai_images` with a remote base URL — in which case every prompt
goes to that endpoint. The Ollama composer talks to whatever
`PPG_OLLAMA_BASE_URL` points at, which is normally localhost.

`data/ppg.db` stores every prompt, persona and attribute set you have ever
generated. Treat it as you would any other application database.
